# Kinoteka — безопасность пользовательских данных в GitHub

Пользовательская библиотека оригинальной версии хранится в SQLite-базе, в таблице `state` внутри JSON-поля `payload`. Для публикации была **создана новая база на основе схемы**, а не удалены строки из старого файла. Поэтому в чистой базе нет даже остатков пользовательских записей на свободных страницах SQLite.

- В `seed-data/kinoteka.sqlite3`: **0 фильмов/сериалов, 0 избранных, 0 элементов корзины, revision=0**.
- Рабочая `data/kinoteka.sqlite3` отсутствует среди отслеживаемых файлов Git.
- Обе SQLite-базы Clean Portable — идентичные копии новой демо-базы.
- Проверки исходников требуют строго SHA-256 `772905b6dac60f266bbc0ea131e085802dcf0b3f41b8f20b5bf23d4bfb90d436` и отсутствие личных записей.
- Резервные копии, SQLite WAL/journal, секреты исключены из Git через `.gitignore`.
- Исполняемый файл `Kinoteka.exe` сохранён без изменений из оригинального Stable-релиза.

Демонстрационная база **не содержит** названий, оценок или метаданных исходной пользовательской библиотеки.

### Важные правила

1. После клонирования запустите `INIT-DEMO-DATA.cmd` до `npm run verify` — команда копирует чистую базу только при отсутствии рабочей БД.
2. Никогда не добавляйте реальную базу через `git add -f` и не коммитьте резервные копии.
3. Для хранения личной библиотеки используйте собственные локальные резервные копии, не Git.
4. Исходная редакция для GitHub не включает бинарные web-шрифты. При локальной сборке используйте установленный Inter или системный шрифт. Выпущенный ранее EXE остаётся неизменённым.
5. Перед публикацией новой версии повторно проверьте, что данные в Portable обезличены.
